# 稳定性评分重构规格

## 1. 背景

当前稳定性评分把“可连接性”作为主要权重。现有可连接性规则是：一次采样里 `ICMP 成功` 或任意 `TCP 端口成功`，就认为本次可连接。这个规则适合判断目标是否“活着”，但不适合作为稳定性核心指标。

稳定性应回答的问题是：这条 VPS 线路在真实使用中是否持续可用、少丢包、少断流、少忽快忽慢。单次可连接存在偶然性，不能主导稳定性排名。

## 2. 目标

- 删除稳定性评分中的“基础可连接性”子指标。
- 将稳定性重构为三个核心指标：连续失败、丢包率、延迟抖动。
- 引入负向激励：严重坏信号允许给负分，不能只是不加分。
- 用人能理解的分档规则替代连续失败和丢包率的线性扣分。
- 保持最终展示总分仍为 `0..100`，避免报告出现负总分造成用户困惑。

## 3. 非目标

- 不改变探测命令本身。
- 不改变历史缓存和白天/晚上交叉验证机制。
- 不改变性能评分中的平均延迟、P95 延迟、TCP 连接耗时、路由跳数逻辑。
- 不引入机器学习或自动调参。

## 4. 新稳定性指标

### 4.1 连续失败，权重 45%

含义：看线路有没有一口气连续断好几次。连续失败代表短时间不可用，对 SSH、代理和服务部署最致命。

计算输入：`TargetMetrics.consecutive_failures`。

评分规则：

- 连续失败 `0` 次：`100` 分。
- 连续失败 `1` 次：`80` 分。
- 连续失败 `2` 次：`50` 分。
- 连续失败 `3` 次：`0` 分。
- 连续失败 `4` 次：`-50` 分。
- 连续失败 `>= 5` 次：`-100` 分。

### 4.2 丢包率，权重 40%

含义：看线路在一段测试窗口里是不是经常掉包。丢包率比“某一次是否可连接”更严格，因为它统计的是持续通信质量。

计算输入：`TargetMetrics.icmp_packet_loss_rate`。

评分规则：

- 丢包率 `0%`：`100` 分。
- `0% < 丢包率 <= 1%`：`90` 分。
- `1% < 丢包率 <= 3%`：`75` 分。
- `3% < 丢包率 <= 5%`：`50` 分。
- `5% < 丢包率 <= 10%`：`0` 分。
- `10% < 丢包率 <= 20%`：`-50` 分。
- 丢包率 `> 20%`：`-100` 分。
- 丢包率缺失：`-100` 分。

### 4.3 延迟抖动与 ICMP 有效性，权重 15%

含义：看成功响应时延迟是否忽高忽低，并处理“成功 ping 过少”这种极差信号。

当前抖动计算方式保持不变：对成功 ICMP 延迟序列，计算相邻两次延迟差值的绝对值，再求平均。

新增输入要求：`TargetMetrics` 需要能表达 ICMP 成功样本数，不能只看总样本数和丢包率。实现时应新增字段，例如 `icmp_success_count: usize`。

先做 ICMP 有效性硬判断：

- 成功 ping 数 `0`：`-100` 分。
- 成功 ping 数 `1`：`-80` 分。
- 成功 ping 数占总样本比例 `< 20%`：`-50` 分。
- 成功 ping 数 `>= 2` 且成功比例 `>= 20%`：正常计算抖动评分。

抖动评分规则：

- 抖动 `<= 5ms`：`100` 分。
- `5ms < 抖动 <= 15ms`：`80` 分。
- `15ms < 抖动 <= 30ms`：`50` 分。
- `30ms < 抖动 <= 60ms`：`0` 分。
- `60ms < 抖动 <= 100ms`：`-50` 分。
- 抖动 `> 100ms`：`-100` 分。
- 抖动缺失且未被成功样本数规则覆盖：`-100` 分。

## 5. 稳定性总分

内部稳定性原始分允许为负数：

```text
稳定性原始分 = 连续失败得分 * 0.45
             + 丢包率得分 * 0.40
             + 抖动有效性得分 * 0.15
```

展示和参与总分时，将稳定性分限制到 `0..100`：

```text
稳定性展示分 = clamp(稳定性原始分, 0, 100)
```

这样内部可以表达惩罚，最终报告仍保持用户可理解的 `0..100` 分数。

## 6. 配置变更

中文 TOML 中的稳定性权重改为：

```toml
["稳定性权重"]
"连续失败" = 0.45
"丢包率" = 0.40
"延迟抖动" = 0.15
```

删除：

```toml
"可连接性"
```

配置校验仍要求稳定性权重之和为 `1.0`。

## 7. 报告变更

报告中的“稳定性权重”应显示：

- 连续失败：`0.45`
- 丢包率：`0.40`
- 延迟抖动：`0.15`

报告不再把“可连接性”列为稳定性权重。

IP 详情可以继续显示可连接率，作为辅助观察指标，但它不参与稳定性评分。

推荐理由应体现负向激励的原因，例如：

- `连续失败 4 次，稳定性重罚`
- `丢包率 12.00%，线路质量严重不稳`
- `ICMP 成功样本为 0，稳定性重罚`
- `抖动 75.00 ms，延迟波动严重`

## 8. 测试要求

- 连续失败分档测试覆盖 `0, 1, 2, 3, 4, 5`。
- 丢包率分档测试覆盖 `0%, 1%, 3%, 5%, 10%, 20%, >20%`。
- ICMP 成功样本数测试覆盖 `0, 1, <20%, >=20%`。
- 抖动分档测试覆盖低抖动、中抖动、高抖动、严重抖动。
- 配置解析测试覆盖删除可连接性、增加延迟抖动。
- 报告测试覆盖不显示“可连接性”稳定性权重，显示“延迟抖动”。
- 业务 E2E 继续通过真实三地 IP 流程。
