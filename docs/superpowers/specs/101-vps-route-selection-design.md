# VPS 线路选择工具设计规格

## 1. 背景

用户在购买 VPS 前，会从商家获得若干可测试 IP 以及对应城市。用户希望通过本地网络到这些 IP 的实际探测结果，判断哪个具体 IP 更适合购买，并在报告中明确展示 IP 对应城市，避免只看到裸 IP 难以理解。

本项目构建一个 macOS 优先的 Rust + Tauri GUI 程序，用于读取用户提供的中文 TOML 配置，执行网络探测，生成可解释的排名和 Markdown 报告。

## 2. 主目标

- 读取中文 TOML 配置中的候选 IP、城市、端口、测试参数和评分权重。
- 对每个候选 IP 执行无需部署远端服务的网络探测。
- 根据稳定性、分时段表现和性能指标进行综合评分。
- 在 GUI 中展示测试进度、排名、分项指标、权重和推荐理由。
- 导出中文 Markdown 报告，报告中完整展示每个权重、每个 IP 的城市、评分依据和扣分原因。

## 3. 非目标

- 不实现 HTTP/HTTPS 健康检查，因为购买前无法在 VPS 上部署测试服务。
- 不实现云厂商自动购买、自动下单或商家 API 对接。
- MVP 不实现关闭窗口后的后台常驻定时任务。
- MVP 不保证 Windows 和 Linux 行为，只优先支持 macOS。
- 不导出 CSV。

## 4. 技术方案

采用 Tauri + Rust 混合探测核心。

- 前端使用 Tauri Web UI，负责中文配置展示、测试进度、排行榜、详情页、Markdown 报告预览与导出。
- 后端使用 Rust，负责中文 TOML 解析、配置校验、测试调度、TCP 探测、调用 macOS `ping` 和 `traceroute`、指标聚合与评分。
- TCP Connect 使用 Rust 原生实现。
- ICMP Ping 和 traceroute 在 MVP 阶段调用 macOS 系统命令并解析输出。

选择该方案的原因：Tauri 适合构建清晰易懂的桌面 GUI；Rust 适合实现并发探测、配置解析和评分逻辑；macOS 系统命令可降低 ICMP 和 traceroute 权限复杂度。

## 5. 中文 TOML 配置

配置文件面向用户使用中文表头和中文键名，中文键名统一加双引号。Rust 内部结构体使用英文变量名，并通过 `serde(rename = "...")` 映射中文键名。

示例：

```toml
["探测设置"]
"默认测试分钟数" = 10
"ICMP间隔毫秒" = 1000
"TCP超时毫秒" = 3000
"并发数" = 4
"白天时段" = "08:00-18:00"
"晚上时段" = "18:00-23:30"

["端口设置"]
"默认端口" = [22, 80, 443]

["总权重"]
"稳定性" = 0.50
"分时段表现" = 0.30
"性能" = 0.20

["稳定性权重"]
"可连接性" = 0.60
"丢包率" = 0.30
"连续失败" = 0.10

["分时段权重"]
"白天" = 0.60
"晚上" = 0.40

["性能权重"]
"平均延迟" = 0.40
"P95延迟" = 0.25
"抖动" = 0.20
"TCP连接耗时" = 0.10
"路由跳数" = 0.05

[["候选IP"]]
"IP" = "203.0.113.10"
"城市" = "东京"

[["候选IP"]]
"IP" = "203.0.113.20"
"城市" = "大阪"
"端口" = [22, 443]
```

配置校验规则：

- IP 必须是合法 IPv4 或 IPv6 地址。
- 城市不能为空。
- 端口必须在合法范围内。
- 测试分钟数、间隔、超时和并发数必须为正数。
- `总权重` 内部总和必须等于 `1.0`，允许极小浮点误差。
- 每个细分权重组内部总和必须等于 `1.0`，允许极小浮点误差。
- 任何权重不得为负数。

## 6. 核心数据模型

- `AppConfig`：完整配置。
- `Target`：单个候选 IP，包含 IP、城市和可选端口覆盖。
- `ProbePlan`：一次测试计划，包含目标列表、持续时间、当前时段和并发参数。
- `ProbeSample`：一次采样结果，包含 ICMP、TCP 或 traceroute 的原始结果。
- `TargetMetrics`：单个 IP 的聚合指标。
- `TargetScore`：单个 IP 的总分、分项分、权重、扣分原因和可信度。
- `TestReport`：GUI 展示和 Markdown 导出的统一报告对象。

## 7. 测试流程

一次测试包含以下阶段：

1. 加载中文 TOML 配置。
2. 校验 IP、城市、端口、时段、权重和测试参数。
3. 判断当前测试属于白天、晚上或其他时段。
4. 生成测试计划，将缺省端口补齐为全局默认端口。
5. 按并发数对候选 IP 执行探测。
6. 持续采样，默认 10 分钟，用户可通过 TOML 或 GUI 调整。
7. 聚合每个 IP 的指标。
8. 计算分项分和总分。
9. 生成 GUI 结果和 Markdown 报告。

探测内容：

- ICMP Ping：延迟、丢包率、抖动、连续失败。
- TCP Connect：端口连接成功率、连接耗时、失败原因。
- traceroute：路由跳数和路径摘要。

定时策略：

- 支持用户手动立即测试。
- 支持 GUI 打开时按白天和晚上时段定时测试。
- 如果定时触发时已有测试正在运行，则跳过本轮并在 GUI 中提示。
- MVP 不在 GUI 关闭后继续后台运行。

## 8. 指标聚合

每个 IP 聚合以下指标：

- 可连接率。
- ICMP 丢包率。
- 平均延迟。
- P95 延迟。
- 抖动。
- TCP 成功率。
- TCP 平均连接耗时。
- 连续失败次数。
- traceroute 跳数。
- 测试时段。
- 样本数量。
- 缺失指标列表。

## 9. 评分模型

总分统一为 `0-100`：

```text
总分 = 稳定性分 * 总权重.稳定性
     + 分时段分 * 总权重.分时段表现
     + 性能分 * 总权重.性能
```

默认总权重：

- 稳定性：50%。
- 分时段表现：30%。
- 性能：20%。

稳定性分由以下指标组成：

- 可连接性。
- 丢包率。
- 连续失败。

分时段分由以下指标组成：

- 白天表现。
- 晚上表现。

默认白天权重大于晚上，例如白天 60%、晚上 40%。

性能分由以下指标组成：

- 平均延迟。
- P95 延迟。
- 抖动。
- TCP 连接耗时。
- 路由跳数。

所有总权重和细分权重都必须从 TOML 读取，不能写死在评分逻辑中。GUI 和 Markdown 报告必须完整展示每个权重。

## 10. 缺失指标与降级评分

- traceroute 失败：标注失败原因，作为辅助指标缺失处理，低影响降级。
- ICMP 不可用但 TCP 可用：继续评分，标注“ICMP 探测不可用，丢包率和延迟指标缺失”，结论可信度下降。
- TCP 端口均不可达但 ICMP 可用：保留 ICMP 指标，可连接性降分。
- ICMP 和 TCP 都不可用：可连接性为 0，标记为不可推荐。
- 分时段样本不完整：报告标注“分时段样本不完整”，不声称完整昼夜结论。

缺失辅助指标时，可以对同一分组内可用指标重新归一化。缺失关键指标时，必须同时降级可信度并在报告中说明。

## 11. GUI 页面

GUI 使用中文界面，包含 4 个主页面。

### 11.1 配置页面

- 选择或创建 TOML 配置文件。
- 展示候选 IP 表格：IP、城市、自定义端口。
- 展示探测设置：默认测试分钟数、并发数、白天时段、晚上时段。
- 展示权重设置：总权重、稳定性权重、分时段权重、性能权重。
- 提供“校验配置”按钮。
- 配置错误使用中文提示。

### 11.2 测试页面

- 提供“立即开始测试”按钮。
- 展示当前测试时段：白天、晚上或其他。
- 展示整体进度：已运行时间、剩余时间、当前测试 IP 数、成功和失败采样数。
- 展示每个 IP 的实时状态：IP、城市、当前可连接状态、当前丢包率、当前平均延迟、TCP 成功率。

### 11.3 结果页面

- 展示排行榜：排名、IP、城市、总分、推荐理由。
- 支持展开 IP 详情：稳定性分、分时段分、性能分、权重、实测指标、扣分原因。
- 对第一名显示明确推荐语，例如：“推荐购买：203.0.113.20（大阪），原因：可连接性高、丢包率低、白天表现稳定。”

### 11.4 报告页面

- 预览 Markdown 报告。
- 导出 Markdown 文件。
- 不提供 CSV 导出。

## 12. Markdown 报告

Markdown 报告必须包含：

- 测试配置摘要。
- 权重配置完整列表。
- 候选 IP 与城市列表。
- 排名表。
- 每个 IP 的分项评分。
- 每个 IP 的原始指标。
- 每个 IP 的扣分原因。
- 每个 IP 的结论可信度。
- 缺失数据说明。
- 推荐购买的具体 IP 和对应城市。

报告中的用户可见文案全部使用中文。

## 13. 错误处理

配置错误阻止开始测试，包括：

- IP 格式错误。
- 城市为空。
- 端口非法。
- 权重总和不等于 `1.0`。
- 测试参数非法。

探测错误不导致程序崩溃。程序应保留可用指标，标注缺失项，并按降级规则评分。

系统命令错误处理：

- 启动测试前检查 macOS `ping` 和 `traceroute` 是否可用。
- 命令不存在或输出解析失败时，在 GUI 和报告中提示。
- 命令解析失败不能导致整个测试失败，只影响对应指标。

## 14. 结论可信度

每个 IP 附带结论可信度：

- 高：ICMP、TCP、时段样本完整。
- 中：缺少 traceroute 或少量辅助指标。
- 低：缺少 ICMP，或缺少白天/晚上任一时段样本。
- 不可推荐：ICMP 和 TCP 均不可用，或测试样本严重不足。

## 15. 测试策略

### 15.1 Rust 后端单元测试

- 中文 TOML 表头和键名解析。
- 中文键名到内部结构体字段的映射。
- 权重总和校验。
- IP、端口和时段格式校验。
- 评分模型计算。
- 缺失指标降级评分。
- Markdown 报告生成。

### 15.2 Rust 后端集成测试

- 用本地测试端口模拟 TCP 成功连接。
- 用关闭端口模拟 TCP 失败连接。
- 验证 TCP 超时处理。
- 将 `ping` 和 `traceroute` 封装为接口，使用 mock 输出模拟 macOS 命令结果。

### 15.3 Tauri 命令测试

- 加载配置。
- 校验配置。
- 启动测试。
- 获取进度。
- 导出 Markdown。
- 后端错误转换为中文错误信息。

### 15.4 前端测试

- 配置页面展示中文 TOML 内容。
- 权重错误时显示中文提示。
- 测试进行中时展示进度。
- 结果页面按分数排序。
- 报告页面能预览 Markdown。

### 15.5 macOS 手工验收

- 使用 2-3 个真实商家测试 IP 跑一次快速测试。
- 验证立即测试可完成。
- 验证白天和晚上标签正确。
- 验证排名可解释。
- 验证 Markdown 导出可读。
- 验证禁 ping 或端口不可达时程序不崩溃。

## 16. 验收标准

- 用户可以通过中文 TOML 配置候选 IP、城市、端口、测试参数和权重。
- 程序可以在 macOS 上完成一次立即测试。
- 程序可以在 GUI 打开时按白天和晚上时段触发定时测试。
- GUI 可以展示测试进度、排名、分项分、权重和扣分原因。
- Markdown 报告可以导出，并完整展示权重、IP、城市、指标、可信度和推荐结论。
- 当 ICMP、TCP 或 traceroute 部分失败时，程序可以降级处理并给出中文说明。
- 自动测试覆盖配置解析、权重校验、评分模型、报告生成和关键探测封装。
